# Game of 24：实验协议与记录方案

> 状态：首轮实验协议，已按用户授权完成审查修正。研究参数写在[机器可读配置](./game24_experiment/experiment.json)中，库默认值及最终生效参数在每次运行的 manifest 中补全。已通过 CPU 方法校验及小尺寸随机初始化 Qwen3 + PEFT 集成校验；实际 4B 模型和外部 A100 尚未验证，尚无训练结果。审查后的数据核验、EOS、日志和 checkpoint 规则见第 6 节。方法定义分别见[两步方案](./two_step_gated_grpo_theory.md)与[单步 baseline](./action_mean_grpo_baseline.md)。

## 1. 已确认的任务选择与方法约定

| 项目 | 当前决定 | 来源或边界 |
| --- | --- | --- |
| 模型可见状态 | 每一步重新提供**当前手上的数字**；模型看不到之前的运算、原始题面或其他历史 | 本轮用户明确选择。数字按当前展示位置编号；相同数值的实例也有不同槽位编号。编号每步按当前展示列表重新确定，不向模型传达历史。 |
| 动作与交互 | 一次模型调用只提交一次选两个当前数字及一种运算的动作；环境执行后才能做下一次决策；第一版不输出自由推理文本 | 用户原始要求及本轮补充。不能把一次生成的完整答案切成三步。 |
| 动作等价 | 加法与乘法各自合并操作数交换顺序；**相同数值但不同槽位的实例分别计为动作**；减法与除法的操作数顺序分别计数；不同运算即使产生同一后继数字集合也分别计数 | 用户最新批注修正了此前对重复实例的合并选择。动作键由运算符与当前所选槽位 ID 决定，不能只由数值或后继状态决定。 |
| 数值域 | 中间结果允许负数、零和精确分数；除零非法 | 本轮用户明确选择。环境计算与成功判定应使用精确有理数。 |
| 模型非法动作 | 立即结束该轨迹，终局奖励记 0 | 本轮用户明确选择。语法错误、选不存在的数字、除零及一次输出多个运算均应明确归类；模型服务故障不等同于模型输出非法动作。 |
| 非法动作的统计 | 同状态所有模型非法输出统一记为 `INVALID` 动作，参与动作均值和标准差统计；五种后续动作的门槛只计合法动作；第二步绝对优势筛选只在已观察合法动作中进行 | 本轮用户逐项明确选择。`INVALID` 无有效后继状态，因此自身不能成为通过后续门控的父动作，也不能入选 `β` 修正集合。 |
| 计算资源与更新范围 | 单张 A100 80GB；采用 LoRA 更新 | 本轮用户提供并确认模型及更新方式；LoRA 具体范围和训练预算由助手在第 3 节明确选择，尚待外部 GPU 实测内存。 |
| 初始模型 | `Qwen/Qwen3-4B-Instruct-2507` | 本轮用户确认。正式运行须固定并记录具体模型 revision 与 tokenizer revision。官方模型卡说明它是 4B 的非思考模式模型。 |
| 预实验 | 暂不开展穷举结构分析，也暂不进行冻结模型采样诊断 | 本轮用户澄清“这两项都跳过”；直接准备主训练比较。 |
| 主训练比较 | 单步动作均值 baseline 与完整两步门控方案 | 本轮用户接受此比较。对照所需相同设置见第 5 节。 |
| 消融 | 本轮先运行单步 baseline 与完整两步方案 | “仅 λ”“仅 β”和随机/无门控仍是后续研究建议；首轮配置没有把这些尚未定义的对照暗中加入。 |
| 数据划分 | 保留 ToT 官方零基索引 `[900,1000)` 的 100 道题用于测试；其余 1262 道按原始难度分层，126 道验证、1136 道训练；同一数字多重集不得跨划分 | 用户确认原则，助手选定每百题一层按固定哈希抽 10 道、末层 62 题抽 6 道，种子为 `20260926`。`prepare` 会保存完整题目 ID 清单和数据哈希。`4 5 6 10` 在测试段，不作训练或提示示例。 |
| 方法核心 | `A^state` 的动作均值等权标准化、按访问位置取前 20%、子状态至少 5 种已观察到的合法动作、σ 门、λ/β 修正、重叠公式与逐 token GRPO/KL | 现有两份方法文档及 Game24 的 `INVALID` 特例；首轮超参数已由助手按授权选定。 |

把当前数字按固定顺序呈现，状态键由当前数字**多重集**确定，例如 `{5,6,6}`。模型可见表示可为 `[1:5, 2:6, 3:6]`：`1×2` 与 `1×3` 是两个动作，`1×2` 与 `2×1` 是同一个动作。模型不见历史，所以在本交互协议中，相同多重集就是相同可见决策状态。编号只代表当前按固定顺序展示的槽位，不跟踪原始数字或此前的表达式树。实现时应保持提示模板、可见字段和编号规则一致，并逐条记录实际提示与模型输入，以验证确实没有泄漏历史。环境可在内部保留表达式树以验证“原始四数各用一次”，但不向模型显示它。

这个动作判等选择会让两个动作在执行后到达完全相同的可见状态。例如上述两个乘法动作都到达 `{6,30}`。在只看当前数字、后续按同一策略决策的协议中，它们的真实后续成功率应相同；有限样本中若估计均值不同，不能直接解释为实质性的第二步分化。记录中应标记“不同动作、相同后继状态”的组及各组样本数，用于解释五动作门槛和标准差；按用户选择仍分别计数，不私自合并或增设可靠性门。

## 2. 建议的执行顺序及停止边界

1. 使用第 3 节已选定的固定配置和对应实现，先在 CPU 上核对环境、动作判等、分组优势、门控、重叠及逐 token 目标。当前已完成这部分单元验证；它不能替代外部 A100 上的集成验证。
2. 外部 A100 接入后，锁定模型 revision、官方数据哈希和具体划分清单，再从同一初始模型启动主比较。每个训练组在自己的更新轮次用其旧策略采样；如果需要核对优势计算，可以使用确定性的手工轨迹或同一批已有训练轨迹，不另外开展冻结模型采样诊断。
3. 用正式训练本身产生的轨迹报告动作覆盖、分组奖励、门控触发与样本数。这些诊断是记录和解释结果，不作为未经确认的新训练门槛。
4. 最终只用固定的测试集和预先规定的 checkpoint 选择规则报告主结果。运行成功、实现符合方法、结果支持研究假设应分别判断。

先前提出的“50 道开发题、每题 256 条轨迹”属于已取消的冻结采样诊断预算示例。首轮正式训练另选每次更新 8 道训练题、每题 256 条完整轨迹，见第 3 节。

## 3. 经用户授权选定的首轮配置

| 范围 | 首轮确定的设置及影响 |
| --- | --- |
| 动作判等 | 最新确认相同值的不同槽位实例分开；加乘仅在**同一对槽位**内合并交换顺序；减除方向分开；不同运算即使得到相同后继状态也分开。需要把这些已确认规则写入动作解析、`d_s` 计数和日志。 |
| 合法运算 | 已确认允许负数、零和精确分数，除零非法。四个数依次做三次合法二元运算；第三次后仅剩 24 才成功。没有用户授权的基于可解性提前停止。 |
| 模型输出 | 每步只生成一次 `左槽位 右槽位 运算符` 调用，不生成自由推理文本；最多 32 个新 token，模型必须发出锁定 checkpoint 的 EOS 集合中的任意一个 token。当前官方配置为 `151645/151643`，运行时核对锁定值；实际 EOS 计入训练目标，EOS 后的 padding 排除。用尽长度未发出 EOS 则作为 `generation_limit` 非法输出、终奖 0。全部实际生成 token 共用步优势。 |
| 非法动作和故障 | 模型生成的非法动作立即结束且终奖为 0；语法、槽位、除零和生成长度错误分别记录，统计时合为 `INVALID`。模型服务失败或硬件中断直接使本次运行失败，不把它们伪装成模型非法动作，也不自动重试或跳样本。 |
| `INVALID` 与第二步筛选 | 已确认 `INVALID` 参与同状态动作均值/标准差以及由此计算的 `A^state/A_2`，但不满足“五种合法后续动作”门槛中的一种。第二步按 `|A_2|` 选择时排除 `INVALID`，`m(d)=ceil(d/2)` 的 `d` 为已观察合法动作数。该任务规则是用户确认的 Game24 特例，与通用方法文档的无异常动作表述区分。 |
| 模型和资源 | `Qwen/Qwen3-4B-Instruct-2507`，运行准备阶段解析并锁定模型 revision；单张 A100 80GB。LoRA 目标为 `q/k/v/o/gate/up/down_proj`，秩 16，alpha 32，dropout 0。实际内存和速度尚待外部 GPU 验证。[官方模型卡](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) |
| 采样与训练 | 每题 256 条轨迹，每次更新 8 道题，训练题恰好遍历 1 轮，每批旧轨迹只更新 1 次。采样温度 1、top-p 1、top-k 0；生成批量 16、评分批量 16、梯度微批量 8；三个训练种子 `20260926/27/28`。AdamW、学习率 `1e-5`、权重衰减 0、无梯度截断；不采用自动提前停止。 |
| 方法参数 | `ω=1.0`、`λ=0.5`、`β=1.5`、逐 token clipping `ε=0.2`、逐 token KL `κ=0.01`。共同参考策略为冻结的初始模型（禁用 LoRA adapter）；两组共享这些设置及目标归约。数值由助手按授权选定，并非论文或原代码规定。 |
| 评估 | 验证/测试均每题贪心生成一次完整轨迹；训练前、每 10 次更新及训练结束做验证，选验证成功率最高 checkpoint，并列时取更早者。仅在选择后对官方 100 题测试一次；保存逐题结果与调用/token 预算。 |
| 训练/验证划分落地 | 除官方测试段外，按原始排序每 100 题一层，层内固定 SHA256 顺序取 10 道验证；末层 62 题取 6 道。固定种子 `20260926`，得到训练 1136、验证 126、测试 100；`prepare` 产出完整清单。 |
| 诊断阶段 | 已确认结构穷举与冻结模型采样诊断都暂缓。训练过程中仍保留记录，以便核对和解释门控。 |

## 4. 应保存的完整记录

建议采用带版本号的结构化日志；下面列的是**应保留的信息**，不是要求引入新的筛选、缓存或训练规则。原始记录应能重算每个 `q_s(a)`、门控、优势和最终指标。日志中所有计数都标明分母及计数单位（题、轨迹、状态、访问位置、动作或 token）。随机并列决策应保存随机种子和实际抽中的 ID。日志从正式训练及评估直接产生，不要求额外预实验。

| 粒度 | 至少记录的字段 |
| --- | --- |
| 一次运行 `run` | 唯一运行 ID、时间、代码版本与未提交改动标识、配置文件及最终生效参数、数据文件校验值、训练/验证/测试题目 ID、模型和 tokenizer 版本、初始/旧/参考策略标识、提示模板版本、环境与校验器版本、随机种子、运行机器与软件版本、实验组名。每轮旧策略和 checkpoint 的变更另记。 |
| 一道题 `puzzle` | 原始四数及标准化多重集、数据划分、来源索引、各次尝试 ID、每次成功/失败、失败类别和所用模型调用与 token 数。 |
| 一条轨迹 `trajectory` | 题目 ID、策略版本、采样参数、轨迹 ID、逐步记录 ID 顺序、终止原因、终局奖励、最终数值、由环境重建的表达式、表达式校验结果、合法/非法动作数、实际模型调用/生成 token/耗时。超时或服务故障与模型生成非法动作分开记录。 |
| 一次决策 `decision` | 决策位置、模型实际可见状态多重集与当前槽位编号、实际输入提示或其无损引用、原始模型输出、生成 token ID/文本及目标 mask、解析结果、规范化动作及动作等价键、被选择槽位 ID 和数字值、运算、环境计算结果、后继状态、是否合法及错误类别、工具返回、停止原因、旧策略逐 token logprob。非模型生成的提示和工具观察需标记为非训练目标。 |
| 每个状态 `state_stats` | 状态键、访问位置 ID、访问数 `K_s`、不同合法动作数、不同**已观察合法**动作数、不同**统计用**动作数（含观测到的 `INVALID`），各动作访问数 `n_s(a)`、该动作所关联的成功/失败计数与平均终奖 `q_s(a)`、不同统计用动作等权均值与总体标准差、每种动作的 `A^state`。另外保存每个动作的后继状态键，以及“不同动作但后继状态相同”的分组和各动作样本数。重复访问同一状态逐次计数，但可标识共享的轨迹 ID。 |
| 第一轮筛选 `parent_gate` | 状态 ID、`K_s`、`ceil(0.2K_s)`、每个访问位置的 `A_1` 与绝对值、排序边界、并列候选与随机抽中位置、去重后的候选动作、父标准差及零方差原因。记录所有入选与未入选位置，不能只保存通过者。 |
| 子状态门控 `child_gate` | 父状态/候选动作/子状态 ID、子状态全部访问位置、各 `a'`（包括观测到的 `INVALID`）的 `n/q/A_2`、实际观察到的不同合法动作数与统计用动作数、子标准差、`σ_child/σ_parent`、五动作门与 `ω` 门各自的真假及失败原因、已观察合法动作数 `d` 与 `ceil(d/2)`、合法动作中的绝对优势排序/边界并列/随机入选的 `a'` 集合。失败的候选也保留。 |
| 优势分配 `advantage` | 每个访问位置的 baseline `A^state`、是否第一轮入选、其动作是否通过门控、是否得到 `λ`、是否位于通过门控链的第二步、当前 `a'` 是否入选、`β A_2`、是否重叠、最终优势 `Â`，以及构成最终优势的各项；记录复核用的固定旧轨迹批次 ID。 |
| 每次策略更新 `update` | 训练组、旧/当前/参考策略版本、所用轨迹 ID、生成 token 数及 mask、逐 token 新旧概率比、clipping 生效比例、逐 token KL 与系数、步内/轨迹内/批次归约结果、目标值、梯度和参数更新统计、优化器状态引用、checkpoint 与配置引用。保存能重算目标的充分信息；若体量过大，可无损分片并记录校验值。 |
| 每次评估 `eval` | checkpoint、测试题 ID、尝试次数、解码参数、每次完整交互及正确性、题级成功指标、非法动作率、生成 token/调用数和成本。保存题级结果，用题目而非同题多条轨迹作为独立统计单位。 |

汇总表另外记录：各层状态及动作覆盖分布、`d_s≥5` 的比例、父子零方差比例、各门单独和共同通过率、获得 λ/β 的访问位置比例、重叠触发次数、第一轮入选者的实际 `|A_1|` 分布、各 `n_s(a)` 的分布、各组训练成功率与置信区间、非法动作率、总模型预算。分析完整两步链时同时报告进入子状态的概率、进入后选到正/负 `A_2` 动作的条件概率，以及二者相乘对应的完整分支频率。分支的“好/坏”定义和估计样本必须在分析前固定；观测频率与模型解析后的动作概率须区分。

以上日志不意味着增加可靠性门、自动重试、缓存、提前停止、密集奖励或用穷举解标记来训练。若之后希望加入任何一项，应作为方法变更单独确定，并在两个训练组中一致处理适用部分。

## 5. 主比较的对齐要求

两组从同一初始 checkpoint 开始，共享题目划分、环境规则、提示与动作判等、终局奖励、**每题尝试轨迹数及每次调用上限**、优化器、更新参数范围、token mask、逐 token clipping、KL 及归约、评估协议。由于非法动作会提前结束轨迹，两组实际模型调用数与生成 token 数可能不同；应如实记录并在比较中报告，不能声称这两个实际预算必然相等。每个训练组按其自身旧策略采集每轮轨迹。单步组只使用 `A^state`；完整两步组按已有文档使用第一轮近零筛选、五动作门、σ 门、λ/β 修正和重叠公式。手工构造的轨迹或已有训练轨迹可以用于核对两种优势与日志；不另行开展冻结模型采样诊断。

若资源允许，另外定义只含 λ、只含 β 的消融。随机/无门控对照若要运行，需事先规定保留多少修正位置、如何匹配调用/样本预算。对照定义、验证集调参范围和实际执行的组别，应在正式结果产生前写入最终配置。

## 6. 审查后的实现补齐与记录口径

2026-09-26 用户授权按审查建议完善实现。本次采用以下规则；终局奖励、动作判等、优势公式（含重叠）、五动作门、超参数、数据划分算法、采样预算与评估次数仍按前文已确定设置执行。

1. **完整 EOS 集合。** `prepare` 从锁定 revision 的 `generation_config` 保存全部 EOS ID 和 padding ID，模型和 tokenizer 使用同一仓库 revision。`run` 再次检查这些值；生成、截断和解析共用相同 EOS 集合。每个决策记录实际 `termination_token_id`，防止合法终止被记为长度错误。

4. **逐 state 门控汇总。** 每个 `stats_XXXX.json` 的 `states[].gate_summary` 直接记录访问数、第一轮入选位置数、候选动作数、五动作门通过数、σ 门通过数、共同通过动作数、失败原因，以及 λ/β/重叠实际作用的访问位置数。`passed_candidate_action_fraction` 的分母是候选动作数，无候选时为 `null`。同一动作的多次访问只计一次动作门控；获得 λ 的访问位置逐次计数。父状态零方差单列，不能遗漏成“没有失败”。
5. **baseline 诊断与实际更新分开标记。** 两组都可以在自身已有轨迹上计算两步诊断。baseline 的 `gate_usage` 为 `counterfactual_diagnostic_only`，所有实际 λ/β 作用次数为 0，`advantages[].applied_advantage` 始终等于基础优势；`final` 仅为该批数据按两步规则计算的对照值。`*_eligible_visit_count` 是两步规则的资格数，`*_applied_visit_count` 才是当前组实际作用数。
6. **训练内诊断。** 记录并在控制台显示零成功批次、零策略优势和两步组无门控通过；每个 state 另记录单样本动作数及同后继状态动作组的样本数。这些诊断只报告已有训练轨迹，不增加可靠性门、额外采样、冻结模型诊断、重试或提前停止。稀疏奖励和小样本方差风险仍需用实际日志解释。每批只更新一次时，clipping 通常不会明显生效。
7. **逐更新审计快照。** 初始及每次更新后（含当次计划内验证）保存 trainable 参数、优化器状态、Python/Torch/CUDA 随机状态及计划/更新标识；固定基础模型由锁定 revision 恢复。当前每组每种子共 143 个快照。`checkpoints.jsonl` 记录 SHA256 与字节数，更新日志关联旧/新策略快照，最佳 checkpoint 记录对应文件。首轮更新后保存快照总存储量估算，供外部主机安排磁盘；rollout/token 日志另计。快照用于审计和复现，没有引入自动恢复失败实验。
8. **运行保护与最终参数。** 拒绝复用非空目录时保留原 manifest。manifest 保存 AdamW 实际参数组（包括 betas、eps 等默认值）、LoRA 实际配置、模型生成配置与训练/评估覆盖项、运行环境和 tokenizer revision。源码哈希使用统一的 `/` 路径和 LF 文本行尾，以便 Windows 工作区与 Linux 外部主机核对。新计划采用 schema 2，旧计划须重新 `prepare`。
