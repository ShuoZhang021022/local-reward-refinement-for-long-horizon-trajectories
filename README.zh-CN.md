# 长程轨迹的局部奖励微调

[English](README.md)

## 项目蓝图

本项目探索一种面向长程轨迹、尤其是代码智能体（code agent）轨迹的群体相对策略优化（GRPO）扩展方法。核心问题是：能否把轨迹层面的反馈更有意义地分配到各个步骤，让策略梯度更新获得更有信息量的学习信号。

当前仓库只有研究蓝图，尚无算法实现或实验结果。

## 研究动机

一次较长的代码智能体运行往往包含许多决策，最后才得到结果。单一的轨迹级奖励难以说明哪些步骤起了正面或负面作用，也难以判断哪里值得继续探索。拟研究的方向是：利用经过某个状态的历史轨迹，以及这些轨迹后续分支之间的关系，细化局部奖励或优势信号。

## 构想一：利用历史轨迹细化局部奖励

对于给定状态，收集经过该状态的历史轨迹，观察它们在下一步所作的选择。研究这些选择的 token 熵，作为局部不确定性或多样性的候选指标。再用图表示共享状态、下一步选择及后续结果，通过图结构和不同后续分支之间的相对比较，探索如何把轨迹反馈重新分配到各步骤。

目标是为 GRPO 构造候选的局部学习信号；其精确定义和策略更新规则仍待确定。特别是，熵所依据的分布、状态匹配标准、图的构造方式和奖励重分配规则，都是尚未确定的研究决策。

## 构想二：利用优势信号引导探索

类似的历史与相对关系分析也可以用于下一步操作的优势值（advantage）。绝对值较大的优势可能表示该操作的观测效果比较明确，同时也可能意味着该分支已经得到较充分的探索。接近零的优势提供的方向性信号较弱；如果覆盖度或不确定性表明继续采样有价值，就可以考虑从这里开辟新的、更深的轨迹。

这些解释目前只是待检验的假设。优势接近零，也可能是因为各选择确实效果相近，或估计噪声较大，不能仅凭其数值断定存在未挖掘的潜力。本项目拟研究能否结合优势幅度、覆盖度与不确定性来分配额外探索资源。

## 实现前需要明确的问题

1. 在代码智能体轨迹中，状态和步骤如何定义？什么条件下两个状态算作相同？
2. 下一步 token 熵来自策略分布、历史轨迹中选择的经验分布，还是其他分布？
3. 图的节点、边及后续结果的相对比较如何定义？
4. 如何根据图计算局部奖励或优势，并将其纳入 GRPO 目标？轨迹级奖励总量是否保持不变？
5. 哪些参数接收梯度？历史轨迹如何采样与更新？
6. 什么条件触发深度探索？探索预算、深度和失败处理规则是什么？
7. 使用哪些任务、数据划分、基线和评估指标检验奖励归因与长程代码智能体性能？
