# 长程轨迹的局部奖励细化

[English](README.md) · [原项目构想](idea.zh-CN.md)

本项目研究**长程语言智能体轨迹中的信用分配**。当智能体经过多次决策后才得到终局反馈时，把同一条轨迹的结果直接用于每一步，可能难以分辨哪些局部选择真正有帮助。我们尝试利用到达相同决策状态的多条轨迹，为动作层面的训练提供更局部的信号。Code agent 是重要的应用动机；当前先在可控的逐步交互任务中检验方法。

## 当前方法

仓库在相同的任务协议下比较两种方法：

1. **单步动作均值 GRPO baseline。** 在同一决策状态下，按下一步动作对已观察轨迹的访问位置分组，先求每个动作对应的平均终局奖励，再对不同动作的均值等权标准化。选择该动作的访问位置获得相应的状态—动作优势。
2. **两步门控细化。** 先找出第一步优势绝对值最小的一部分访问位置，再检查其后继状态中已观察到的下一步动作相对于父状态是否具有足够的动作均值离散度，并满足动作覆盖门槛。通过门控的分支中，给入选的第一步访问位置增加进入后继状态的优势增量，并放大入选第二步动作的**带符号**优势。其他访问位置沿用单步优势；相邻两步链重叠时按文档中的加法规则处理。

[两步方法规范](experiment/game24/two_step_gated_grpo_theory.md)和[单步 baseline 规范](experiment/game24/action_mean_grpo_baseline.md)给出了准确的筛选数量、门控条件、公式、重叠规则和策略目标。各任务的特例与具体设置见实验协议和配置文件。在**当前实现**中，一次动作或工具调用是一个决策步骤：同一步生成的 token 共享该步优势，但策略概率比、裁剪及 KL 按 token 计算。因此，当前的信用分配仍是**步骤级**，不是 token 级的奖励细化算法。

## 实验与当前进展

| 任务 | 仓库已有内容 | 首轮计算资源计划 |
| --- | --- | --- |
| [Game of 24](experiment/game24/README.md) | 逐步运算环境、有来源记录的官方数据、已锁定的计划、训练代码、测试以及 baseline 与两步方案的配对协议 | 一张 A100 80 GB |
| [六块积木 Blocksworld](experiment/BlocksWorld/README.md) | 基于 PlanBench Blocksworld-4ops 的逐步交互改编、符号环境、数据生成与审计说明、训练代码及配对协议 | 一张 A100 80 GB；数据生成需要 Linux |
| [五次阅读 HotpotQA](experiment/hotpotqa/README.md) | 基于 HotpotQA distractor 的选择性阅读改编、八卡训练流程、测试及配对协议 | 一台配备八张 A100 的 Linux 服务器 |

这些是首轮实验计划，所列硬件并非已经实测充分的保证。Blocksworld 与 HotpotQA 是独立的交互式改编协议，不对应官方榜单分数。各实验指南记录了本地方法校验和合成样例集成检查。**目前尚无完成的预训练模型训练对比，也没有可报告的经验性能结果。**[英文方法说明](output/pdf/two_step_gate_grpo_en.pdf)及其 [LaTeX 源文件](paper/main.tex)介绍方法，不包含实验结论。

## 正在推进的方向

- **Token 级变体：** 我们正在考虑进一步在一次动作生成的 token 内部分配或细化信用。目前尚未确定其目标函数、归因规则和评估协议，也尚未纳入现有实验。
- **计算资源与实证评估：** 目前正在寻找计算资源，以完成计划中的预训练模型对比，并分析门控行为、任务表现和实际计算开销。
- **长程智能体：** 完成可控任务的验证后，希望研究该思路能否迁移到更长的工具使用与 code-agent 轨迹；这仍是研究方向。
